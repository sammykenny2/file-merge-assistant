# Internationalization

File Merge Assistant shows its text in English or Traditional Chinese. The user picks the display language in
Settings > General > Display language. The rules follow desktop-work-fleet's `docs/i18n.md`; the decision is
[ADR-014](decisions/ADR-014-tray-startup-and-display-language.md).

## Locales and the language preference

- Supported locales: `en` (the default and the fallback for any missing text) and `zh-TW`.
- The preference is `auto`, `en` or `zh-TW`; a new computer starts at `auto`. It is stored in the `language` field of
  `host-preferences.json` in the data folder, beside the index, and belongs to this computer.
- `auto` walks the Windows display languages (`GetUserPreferredUILanguages`) in order and takes the first that matches:
  - `en` and any `en-*` tag map to `en`.
  - `zh`, `zh-TW`, `zh-Hant`, `zh-HK`, `zh-MO`, and tags that start with `zh-TW-`, `zh-Hant-`, `zh-HK-` or `zh-MO-`,
    map to `zh-TW`.
  - Simplified Chinese (`zh-CN`, `zh-Hans`, `zh-SG`, ...) and every other language do not match; the walk continues.
  - Nothing matching means `en`.
  - Matching ignores case, treats `_` like `-`, and drops a POSIX encoding or modifier (`zh_TW.UTF-8` is `zh-TW`).
- The app resolves the language first thing at startup, before the tray icon or any dialog appears.

## Settings

Settings > General has one row, **Display language**, with a drop-down. As in desktop-work-fleet, each option is named
in the current display language and "Auto-detect" never names the language it resolved to:

- English: `Auto-detect`, `English`, `Traditional Chinese`.
- Traditional Chinese: `自動偵測`, `英文`, `繁體中文`.

Choosing an option stores it and switches the window, the tray menu and the app's own dialogs at once, without a
restart.

## Catalogs

- `src/Core/Localization/AppText.cs` holds the rules and the lookup: `AppText.Get(key, ("name", value))` in the
  current language, `AppText.Format(locale, key, ...)` in a given one, `Apply`, `Match`, `Resolve` and the `Changed`
  event. Core and the GUI both use it, so messages from Core (update errors, run results) are localized too.
- Each area keeps its strings in its own file, `src/Core/Localization/AppText.<Area>.cs`, as two dictionaries,
  `<Area>English` and `<Area>Chinese`, between `// i18n:en`, `// i18n:zh-TW` and `// i18n:end` marker comments, one
  entry per line. Every key starts with the area's name in lower camel case and a dot (`settings.general.language` is
  in `AppText.Settings.cs`).
- Placeholders are `{name}`. A missing value leaves the placeholder visible. Never build a sentence from translated
  fragments; give the whole sentence one key, because word order differs.
- A key missing from Chinese falls back to English, and a key missing from English returns the key itself.
  `tests/Core.Tests/Localization/AppTextTests.cs` fails before either can ship: both tables of every area must have
  the same keys and placeholders, keys must start with their area, and no key may be defined in two areas.
- Numbers, sizes and dates are formatted in code; dates use `AppText.Culture`.

## WPF

- XAML takes catalog text with the `T` markup extension: `Text="{l:T settings.title}"`, with
  `xmlns:l="clr-namespace:FileMergeAssistant.Gui.Localization"`. It binds to `Loc.Instance[key]`, which raises a change
  for every key when the language changes, so bound text switches by itself.
- Text a view model builds in code (`AppText.Get(...)`) redraws when `MainViewModel` hears `AppText.Changed`: it
  rebuilds the header and calls `Refresh()` on the current screen. A screen's `Refresh()` must therefore rebuild every
  string it shows, child view models included, without losing choices the user has not submitted.
- Text the stores make from the index (stack titles and evidence, plan check details, scan job lines) follows the
  language too: `IndexedWorkbenchStore` reads the index again after a change and raises `Changed`, and the demo store
  rebuilds its sample text. For a moment after a switch, the open screen may show the previous language.
- `Fmt` formats dates per language (`Today 09:12`, `Oct 22`; `今天 09:12`, `10/22`) and joins lists, clauses and
  sentences with each language's punctuation (`Fmt.List`, `Fmt.Clauses`, `Fmt.Sentences`).
- The tray reads its labels each time its menu opens.

## What stays in one language

- Error codes (`UpdateException.Code`, journal states) are stable English identifiers for logic.
- Text that was written into the index keeps the language it was written in: recorded reasons in the run history,
  restore results, scan job reasons and drive descriptions.
- The suffix of a file restored beside what now occupies its place (`(restored 10-24)`, `(還原 10-24)`) is part of a
  file name on disk, in the language of the moment it was restored.
- Sample data in `--demo` (folder, file and drive names) stays as it is; the sentences around it are translated.
- The setup program has its own English and Traditional Chinese strings (`installer/FileMergeAssistant.nsi`) and
  follows the Windows language, not the app's setting.

## Tests

Both test assemblies pin the language to `zh-TW` when they load (`TestEnvironment`, `WpfHost`), so tests that compare
screen text do not depend on the language of the Windows they run on. Tests that switch the language run in the
non-parallel `Display language` collection and switch back afterwards.
