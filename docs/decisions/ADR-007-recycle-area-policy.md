# ADR-007：回收區的位置、保存期限與清理（D-04）

## 狀態

Accepted（2026-10-23：產品負責人同意依提議實作，見 PR #10）

## 背景

- [產品需求](../requirements.md) 規定第一階段以可追蹤的回收／隔離方式移除檔案；移入回收區不等於釋放空間。
- 現行 [`RecycleBinService`](../../src/Core/Services/RecycleBinService.cs) 預設把檔移到 `file-workbench-results/.recycle-bin`，這個路徑相對於程式啟動時的工作目錄，並以 `manifest.json` 記錄。程式有 `PurgeAsync` 與 `PurgeOlderThanAsync`，但沒有保存期限設定；GUI 目前只提供全部還原。
- 跨磁碟移動等於複製再刪除。把 E:\ 的檔移進 C:\ 的回收區，會佔用 C:\ 的空間，也比較花時間。
- 外接硬碟拔掉後，放在它上面的回收內容就無法還原。
- FR-010 要求資料位置不隨工作目錄改變。

## 決策（提議）

- 每個磁碟區使用自己的回收區，例如該磁碟區根目錄下的隱藏資料夾。同一磁碟區內的移動不需要複製資料。
- 回收紀錄與操作歷史集中保存在程式的資料位置（見 [ADR-012](./ADR-012-release-packaging.md)），並記錄每筆回收內容所在磁碟區的身份（見 [ADR-010](./ADR-010-source-identity.md)）。
- 外接磁碟離線時，它上面的回收項目顯示為「接上後才能還原」。
- 保存期限先提議預設 30 天（建議值，待決定）。到期前提醒使用者，由使用者確認後才清空；不自動永久刪除。
- 介面分開顯示「回收區目前佔用」與「實際已釋放」。清空後，相關批次標示為不能還原。

## 影響

### 正面

- 同一磁碟區內移動很快，也不會額外佔用其他磁碟的空間。
- 還原紀錄集中保存，不再隨工作目錄改變。

### 負面

- 需要在每個磁碟區建立隱藏資料夾，並處理沒有寫入權限、唯讀媒體與網路磁碟的情況。
- 回收位置不只一個，清理與空間顯示需要一致。

### 中性

- 現有的 `PurgeOlderThanAsync` 可以作為到期清理的基礎。

## 考慮過的替代方案

### 替代方案一：單一集中回收區（現況）

- **優點**：實作簡單，所有內容在同一個地方。
- **缺點**：跨磁碟要複製；空間集中在一顆磁碟上；位置會隨工作目錄改變。
- **不採用的原因**：不符合 FR-010，跨磁碟時的成本與空間影響也太大。

### 替代方案二：使用 Windows 資源回收筒

- **優點**：使用者熟悉，空間由系統管理。
- **缺點**：逐項追蹤與程式化還原比較困難；使用者或系統可能在程式之外清空它，讓操作歷史中的「可還原」變成不正確。
- **不採用的原因**：無法保證 SPEC-001 要求的可還原紀錄。

### 替代方案三：直接永久刪除

- **優點**：立即釋放空間。
- **缺點**：無法還原。
- **不採用的原因**：違反第一階段「可追蹤回收」的要求。

## 待決定事項

- 回收區放在每個磁碟區，還是集中一處。
- 保存期限的預設值，以及到期時的行為。
- 網路磁碟與唯讀媒體上的檔案要怎麼處理。
