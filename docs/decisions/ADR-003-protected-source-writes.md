# ADR-003：受保護來源在合併時的寫入規則

## 狀態

Accepted（2026-10-23：產品負責人同意依提議實作，見 PR #10）

## 背景

- [產品需求](../requirements.md) 規定：受保護來源可以參與比對，但不能成為移除目標。
- 現行 [`ResolutionService.ApplyProtectedPaths`](../../src/Core/Resolution/ResolutionService.cs) 只把受保護路徑上的 Delete 改成 Skip；Move 等其他動作不受影響，也沒有「寫入」的概念。
- 使用者最常保護的，是正在使用的位置，例如開發中的原始碼或照片庫；這些位置也最適合當正本。[ADR-002](./ADR-002-merge-into-keeper.md) 的合併需要寫入正本。

## 決策（提議）

- 「受保護」的意思是：不移入回收區、不覆寫、不移動。可以新增檔案，但必須同時符合兩個條件：使用者對該疊明確選了「合併到正本」，而且在待執行中確認過。
- 受保護的正本遇到同一路徑內容不同時，不提供「用其他份的版本」，只能保留正本的版本，或兩份都留。
- 正本是 git 工作目錄時，計畫中標示新增的檔會成為未追蹤的檔案。
- 所有會移除、移動或覆寫的動作都要做保護檢查（不只 Delete），並在執行前重新檢查一次。

## 影響

### 正面

- 受保護的位置可以當合併的正本。
- 保護檢查涵蓋所有破壞性動作，補上現行只檢查 Delete 的缺口。

### 負面

- 「受保護」不再等於「完全不碰」，需要在來源設定與待執行計畫中清楚說明。
- 期待受保護等於唯讀的使用者，可能會感到意外。

### 中性

- 不影響受保護來源參與比對與作為建議正本的方式。

## 考慮過的替代方案

### 替代方案一：受保護等於完全唯讀

- **優點**：語意最簡單，最不容易誤解。
- **缺點**：受保護的位置不能當合併正本，使用者必須把正本設在不受保護的地方。
- **不採用的原因**：不作為預設；可以作為另一個保護層級「唯讀」提供。

### 替代方案二：每次寫入受保護位置時另外詢問

- **優點**：使用者每次都知情。
- **缺點**：打斷一疊一疊的整理節奏。
- **不採用的原因**：待執行的確認已經涵蓋同樣的資訊。

## 待決定事項

- 是否需要「受保護（可新增）」與「唯讀」兩種保護層級。
- 合併到受保護正本時，是否要求額外確認。
