# GUI 設計交接

狀態：Draft。最後更新：2026-10-23。

這是一個讓使用者長期整理多個資料夾與硬碟的 Windows 桌面工具。設計目標是讓使用者看懂掃描涵蓋範圍、重複判定與整理影響，能持續累積工作成果，並有把握地決定保留哪些檔案。

請由使用者任務規劃 layout。以下定義所需資訊、操作及狀態，不規定畫面數量、導覽位置、面板分割、配色或 UI 框架，也不要求沿用現有 Scan／Results／Reports 的分頁。

產品範圍見 [產品需求](requirements.md)，狀態與例外行為見 [工作流程規格](specs/SPEC-001-persistent-scan-workbench.md)。這些是設計與驗收草案，功能尚未完成。

第一版可點擊 mock、它的假設與待產品決定的問題，見 [GUI 流程 mock](gui-flow-mock.md)。

## 使用者要完成的工作

使用者可能有一份正在使用的照片庫、多顆備份硬碟，以及不同時間留下的資料夾。檔案名稱不一定可靠，拍攝資訊也可能缺漏。使用者想要省去反覆掃描與人工翻找，同時避免誤刪原始檔或重要版本。

設計需要讓使用者隨時回答：

- 哪些來源已加入？哪些在線、離線或需要更新？
- 正在掃描什麼？完成了多少？接下來會處理哪個來源？
- 這些檔案為什麼被放在同一組？結果有多新、是否完整？
- 哪些檔案會保留？建議的理由是什麼？可以保留多份嗎？
- 確認後會修改哪些檔案？處理到哪裡？還能還原哪些項目？

## 主要任務腳本

### 第一次建立索引

使用者加入 `D:\Photos` 與 `E:\Backup`，設定範圍及排除條件，將兩者加入佇列。掃描過程仍能加入下一個來源；完成後能查看來源內及跨來源的內容重複。

需要呈現空白狀態、來源設定、待執行與執行中工作、目前階段及部分結果。加入來源、開始掃描與刪除來源紀錄必須有可理解的差別。

### 日後加入另一顆硬碟

使用者隔天啟動程式，能看到之前的來源及索引，加入 `F:\OldPhotos` 後與既有內容比對。離線來源仍有最後一次觀察的資訊，但與可立即操作的檔案清楚區分。

設計需表達最近掃描時間、資料是否需要更新，以及新加入來源和比較範圍的關係。

### 審閱一組重複檔案

使用者看到相同照片散落在三個來源。原始照片庫受保護，備份檔名不同，部分 metadata 缺失。使用者查看預覽與差異，接受或調整保留建議，也可以保留兩份或略過整組。

不要以原始 hash 字串作為主要群組名稱。技術性判定資訊需能取得，但主要辨識應依檔案內容、來源及可理解的摘要。

### 確認與執行整理

使用者先看到完整待執行清單，確認保留檔、處理方式與空間估計，才能執行。若其中一顆硬碟已拔除或檔案已改動，系統應指出受影響項目，讓使用者返回更新或略過。

套用保留規則、選取檔案與確認執行需要可辨識的不同階段。未審閱的新項目不能因之前按過確認而自動執行。

### 處理部分失敗與還原

部分檔案已移入回收區，另一些因為被占用而失敗。使用者能辨識結果、重試失敗項目，或按批次／單筆還原。原位置已存在新檔案時，要能理解衝突並選擇處理方式。

## 必須容納的資訊與操作

以下是資訊範圍，不是一對一的頁面或面板指定。

| 範圍 | 必須能取得的資訊 | 主要操作 |
|------|------------------|----------|
| 來源 | 名稱、完整路徑、磁碟／來源識別、在線狀態、最近掃描、保護與排除設定 | 新增、編輯設定、掃描、重新連接／指定路徑、選擇比較範圍 |
| 工作 | 來源、順序、狀態、階段、已處理數、錯誤數及目前項目 | 加入、改待執行順序、暫停、繼續、取消、重試 |
| 重複群組 | 類型、檔案數、來源、新舊程度、審閱狀態與空間估計 | 搜尋、篩選、排序、進入對照、略過、批次套用建議 |
| 檔案對照 | 預覽、檔名、完整路徑、大小、日期、可用 metadata、保留理由及保護狀態 | 保留／取消保留、開啟檔案或位置、建立計畫 |
| 待執行計畫 | 保留與處理項目、動作、目的地、預估影響、驗證狀態 | 審閱、移除項目、返回修改、明確確認執行 |
| 操作歷史 | 批次與單筆結果、時間、錯誤、回收內容是否存在及可還原狀態 | 查看詳情、重試、還原、處理衝突 |

一般流程應先讓使用者表達「比對內容相同」或「檢查相似照片」，不要求先理解 SHA-256、xxHash 或感知雜湊等演算法選項。相似照片屬後續擴充，不能在第一階段原型中呈現為已可用的辨識能力。

## 必須設計的狀態

- **尚無資料**：尚未加入來源、已加入但未掃描、沒有結果、沒有待執行計畫。
- **掃描過程**：等候、探索中、計算中、保存中、正在暫停、已暫停、取消中及中斷待處理。
- **結果範圍**：尚未掃完、掃描含略過／錯誤、索引過期、來源離線及需要重新驗證。
- **預覽問題**：沒有 metadata、檔案類型不支援、縮圖仍在載入、預覽讀取失敗。
- **操作限制**：受保護、保留數為零、來源不可用、檔案已變動、回收目的地不可用或空間不足。
- **執行結果**：全部成功、部分成功、失敗、已取消、可還原、還原衝突及已不可還原。

離線、錯誤及受保護等狀態不能只以顏色區別。不可用的動作要有原因；一般使用者不必從 exception、日誌或資料庫欄位猜測下一步。

## 選取與大量操作

設計需說明目前選取的是檔案、整組還是篩選後的所有結果；「全部」是否包含未載入或未顯示的項目也必須清楚。變更排序、篩選及載入更多資料，不能默默改變保留決定。

保留建議與人工選擇需要能辨識及回復。使用者應知道批次規則會影響哪些群組，並能在執行前檢查例外。受保護項目不可被批次規則覆寫。

## 空間與進度的表達

需要區分重複檔的邏輯大小、目前計畫涉及的大小、回收區佔用及實際釋放情況。移入回收區後，不應立即顯示「已釋放」相同容量。

進度應標示目前階段。尚未知道總量時顯示已處理數；估計時間及百分比需能表達不確定性。錯誤與略過數不能混入成功數。

## 設計驗證方式

後續 layout 請使用清楚標示為模擬的資料，包含多個來源、長路徑、相同檔名、缺少 metadata、離線硬碟及大量結果。至少走完前述五個任務腳本，並檢查鍵盤操作、焦點、捲動與不同視窗大小下的可用性。

請交付：

1. 資訊架構與主要任務的導覽方式，說明哪些內容可以同時存在。
2. 低保真 layout 或可點擊原型，涵蓋主要任務與關鍵例外狀態。
3. 選取、批次套用、保留建議、確認執行及還原衝突的互動說明。
4. 無資料、部分完成、大量資料、離線與失敗狀態的設計。
5. 仍需產品負責人決定的問題，以及對第一階段範圍的影響。

設計評估以任務能否完成、資訊是否足夠及錯誤狀態能否理解為準。後續工程依審閱後的設計評估實作；本次不要求產生 UI 程式碼。
