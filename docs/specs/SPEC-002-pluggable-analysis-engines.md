## 摘要

讓 File Workbench GUI 與 CLI 透過同一個 C# 契約，選用自有 C# 分析或 Rust 包裝的 `czkawka_core`。引擎提供檔案分析證據，File Workbench 保有索引、來源、任務、審閱、執行與還原責任。本規格補充 [SPEC-001](./SPEC-001-persistent-scan-workbench.md)，不改變其完整索引及檔案操作規則。

## 目前基準與目標

以 File Workbench commit `531ab2e45aac4d7d0f7c7aabbdd57b2a2ffee724`（0.2.1）為查閱基準：

- GUI 的 `ScanWorker` 直接建立 `SourceScanner`；探索、指紋與 SQLite 寫入尚未抽離。CLI 仍使用服務式掃描。
- `files.hash` 保存既有帶標記的內容指紋；疊偵測依賴它，執行器的複製驗證也使用現有 XxHash128 路徑。
- 尚無 `IFileAnalysisEngine`、引擎 registry、Rust FFI 程式庫、引擎設定或引擎專用契約測試。下列需求與型別名稱均為目標，不是目前 API。

2026-10-24 Slice 1／2 建立共用契約、registry、C# 適配及 Windows x64 C ABI。
當時尚未接入的持久快照與 GUI／CLI 選擇已由 Slice 3／4 完成，詳見下方及
PLAN-002。以上清單保留為原始查閱基準；目前預設仍是 C# XxHash128。

目前契約使用不可變 record 與 `ImmutableArray`：`AnalysisRequest` 包含 Job ID、`AnalysisEngineSnapshot` 及明確候選；`IFileAnalysisEngine.AnalyzeAsync` 非同步逐批回傳 `AnalysisBatch`，帶序號、逐檔證據、群組、進度及 final／complete 標記。`AnalysisResultValidator` 驗證全部輸出及完整覆蓋；未收到 final、未知／重複 ID、算法不符、無完整相同證據的精確群組均拒絕。C# 目前僅宣告精確內容分析（xxh128-v1、sha256-v1），成熟度為 Experimental，沒有提供相似圖片能力。

Slice 3a 的 schema 4 已加入任務快照及版本化證據表。新任務凍結全部來源、排除／保護設定、磁碟序號與可取得的根目錄身份；恢復先查精確版本，無隱藏切換。舊版未完成任務標為 `NeedsNewJob`，原始備份、完成歷史與回收紀錄保留。重新開始會建立新 ID。證據表的世代提交及程序中斷恢復仍待後續 slice，不把建表視為完成 G3。

Slice 3b 的 schema 5 已接入逐檔證據快取及世代提交。快取要求算法、參數、引擎版本／上游 commit 與大小／時間／可取得身份一致；legacy 證據仍保留原標記，新引擎不繼承其來源。每批先保存證據，完整成功並在發布前重新觀察後，才在單一 SQLite 交易啟用。中斷／暫停不替換上一份完整結果，已確認變動的舊指紋會失效。疊另存內容證據摘要；證據更新或 legacy 決策缺證據時，待執行計畫重新進入人工審閱，原本的 metadata 與複製驗證算法保留。程序中斷及缺原生檔案的冷啟動仍待 Slice 3c。

Slice 3c 已通過 Windows x64 G3：隔離程序損失後保留原快照及檢查點，缺引擎時等待，原版本可恢復同一任務；缺原生程式庫的全新程序仍能讀歷史並還原。這是故障恢復驗證，不是新的程序隔離架構或其他平台支援宣告。GUI／CLI 選擇與相似圖片接線為 Phase 4。

Slice 4a 已提供 WPF 精確內容引擎選擇及任務快照顯示。新任務設定保存至索引，重新開啟仍保留；缺版本或損壞設定可診斷，不自動改用另一個引擎。介面顯示能力、算法、實驗性狀態與可用性，任務顯示固定版本／範圍／參數。既有任務需以新 ID 重新開始才能更換設定；取消及部分分析與成功啟用分開顯示。CLI 與相似圖片仍未完成，不能由此宣告 G4。

## 目標

- 可明確選擇引擎，支援功能與驗證程度不必相同。
- 接入 Rust 核心時保留完整索引、候選優先與可追溯的任務語意。
- 引擎切換、不可用與失敗，都不繞過 File Workbench 的檔案操作流程。
- 為後續多平台 UI 保留共用契約，先完成 Windows 上可驗證的整合。

## 範圍外

- 初次文件提交未包含程式實作；2026-10-24 後續已授權依 PLAN-002 分片實作。未通過驗收前不切換預設值，CI 維持停用。
- 不重寫 GUI、不定案 Avalonia、不移植全部 File Workbench Core。
- 不一次整合上游 14 種工具，不要求 C# 實作與它們功能相同。
- 不透過分析引擎執行刪除、連結替換、EXIF 移除或影片最佳化。
- 不承諾任意時刻可強制終止原生函式，或在同程序原生崩潰後繼續工作。

## 使用者故事


- US-E01：為一個分析任務選擇引擎，知道它支援哪些功能及是否仍為實驗性。
- US-E02：使用相同範圍分別執行兩個引擎，比較結果，不產生兩份重複的檔案操作。
- US-E03：重新開啟程式後，知道原任務的引擎與設定；缺少相依時能看到原因。
- US-E04：引擎更新或切換後，仍可檢視原分析紀錄、操作歷史及可還原項目。

## 功能需求

| 編號 | 需求 |
|------|------|
| FR-E01 | Core 提供 `IFileAnalysisEngine`、引擎描述與 registry；GUI／CLI 不直接依賴 Rust 型別或 P/Invoke。 |
| FR-E02 | 能力、可用性、成熟度分開表達，依平台／架構與實際建置內容判定。未支援、相依缺失及失敗不可等同零結果。 |
| FR-E03 | 引擎選擇在任務建立時固定；任務保存完整設定與版本快照。不得中途切換、以新預設值恢復舊任務或隱藏 fallback。 |
| FR-E04 | File Workbench 探索並保存所有範圍內的檔案，建立跨來源候選集合；引擎只處理核准範圍。上游內部重掃若不可避免，須驗證等價範圍並量測額外 I/O。 |
| FR-E05 | 結果提供可對應 File Workbench 檔案 ID 的逐檔證據、群組、涵蓋範圍、略過與錯誤；內容相同與相似候選使用不同結果種類。 |
| FR-E06 | 工作在背景執行，進度依階段回報；取消與暫停使用明確協定，部分結果不宣告為完整結果。 |
| FR-E07 | Core 驗證及分批提交結果；相依快取、指紋、群組及計畫保存來源版本資訊，避免跨演算法混用。 |
| FR-E08 | 分析引擎不得改動來源檔或直接存取 File Workbench SQLite；保護規則、計畫確認、執行前驗證、回收與還原仍在 Core。 |
| FR-E09 | C# 先提供精確去重的有限實作；Rust 先驗證精確去重契約，再接相似圖片。相似影片為後續能力。 |
| FR-E10 | GUI 與 CLI 使用同一套選擇、驗證與結果契約；CLI 的既有輸出／操作預設不得在接線時靜默改變。 |
| FR-E11 | 原生程式庫採固定版本與受控路徑載入；相依、架構或 ABI 不符時回報可處理的不可用原因。 |

### 能力與預設值

以下為實作順序，不是現有支援矩陣。能力是工作種類，不把 hash 名稱當成引擎名稱。

| 能力 | C# 引擎目標 | Czkawka 引擎目標 | 結果語意 |
|------|-------------|-----------------|----------|
| `ExactDuplicates` | 第一階段；沿用並抽出現有內容分析 | 首輪適配與驗收 | 全檔內容證據；須支撐現有疊與重新驗證 |
| `SimilarImages` | 初期不支援；既有 AverageHash 元件不等於已整合 | 精確去重契約通過後接入 | 依演算法及閾值產生相似候選 |
| `SimilarVideos` | 初期不支援 | 後續；檢查實際功能及 FFmpeg 相依 | 相似候選，不能當成內容相同 |

成熟度至少區分 `Experimental`、`Preview`、`Validated`，並附平台、版本及驗證紀錄；可用性另區分可用、未支援、缺相依與不相容。Rust 成為某項能力的預設值，須先通過對應的 PLAN 閘門。現有預設在那之前不變。

### 任務與結果契約

| 資料 | 最少需要保存的內容 |
|------|--------------------|
| 引擎描述 | 穩定 ID、顯示名稱、實作與上游版本／commit、契約與 ABI 版本、平台／架構、能力及成熟度 |
| 分析請求 | Job ID、來源與檔案 ID、分析功能、範圍／排除／保護快照、候選清單、檔案觀察版本、演算法與參數、資源限制 |
| 指紋證據 | 檔案 ID、大小／時間及可用的系統身份、演算法 ID、編碼／版本、完整或部分內容的標記、值及觀察時間 |
| 候選群組 | 成員 ID、判定種類、證據來源、分數／距離的定義及閾值；不能把不同引擎分數直接顯示成相同百分比 |
| 涵蓋範圍 | 請求與實際處理範圍、完成／略過／失敗項目、是否完整、檢查點與分析世代 |
| 進度與終態 | Job ID、階段、已處理數／bytes、可選總數、部分批次序號；完成、已取消、失敗或等待來源等結果 |

型別的最終 C#／C 宣告在技術驗證時固定。回傳路徑只能對應請求內的檔案，不接受引擎擴大範圍或回傳未知 ID；Core 仍核對檔案是否在分析中變動。離線來源可供歷史瀏覽，但不能假裝已由本次原生分析重新確認。

### 探索、指紋與索引相容

1. 將探索及索引提交從分析實作分離；File Workbench 依 ADR-004 保存完整清單、建立候選並排程。
2. 原生適配必須證明能取得契約需要的逐檔證據，而不只取得「找到的重複群組」。同大小但不重複的候選，也要能說明其完成／略過／失敗狀態。
3. 上游未公開足夠資料時，先記錄可行的最小 API 擴充、維護與授權方案；不直接把內部結果當成完整索引，也不在本文件工作中修改外部 fork。
4. 引擎快取限於各自版本與工作目錄。持久指紋按演算法、編碼與參數版本比對；新資料不覆寫成舊 `xxh128:` 意義。
5. 遷移前備份，舊紀錄保留可辨識的 legacy 來源。舊任務缺少引擎快照時須標記，不能自行推定 Rust；不能安全恢復時保留紀錄並明示建立新分析。
6. 受新證據影響的疊及待執行計畫重新驗證。舊操作歷史、回收紀錄與還原不得因切換或移除 Rust 程式庫而失效；執行器的既有複製驗證算法獨立保留或明確遷移。

### 進度、暫停與失敗

- 第一版沿用一次一個分析任務的排程；GUI 不在 Dispatcher 上執行分析。原生側的內部執行緒也納入資源設定。
- 沒有可靠總數時只顯示階段與計數。進度事件可合併，結果批次需有大小上限及背壓，避免無限制累積記憶體。
- 取消先停止安排新工作，再等待引擎回應，保持「取消中」直到終態。暫停若無原生檢查點，採合作停止及稍後重做未提交範圍，不能聲稱從任意函式位置恢復。
- 已提交的探索紀錄保留。只有範圍完整且成功的分析世代可以替代既有完整結果；中斷、錯誤或取消不能推論未回報檔案已消失。
- 舊任務需要的精確版本不可用時，記錄不可用原因並提供建立新任務；重新開始的任務有新 ID。不得換引擎繼續同一任務。

### FFI 邊界

- Rust 包裝輸出 C ABI，採固定寬度數值、明確長度的資料緩衝區及 opaque job handle，不直接匯出 Rust 的 `Vec`、`String`、`Arc` 或 channel。
- 協定涵蓋版本／能力查詢、建立及啟動工作、輪詢進度／結果批次、取消、釋放結果與銷毀工作。初版採輪詢，避免把 WPF 或 .NET 物件交給 Rust 背景 callback。
- 接收資料複製或持有的時機、UTF-8 編碼、長度上限、緩衝區所有權與釋放時機必須明訂；Rust 配置的記憶體由對應 Rust 釋放函式回收。
- 返回值區分有效零結果、未支援、無法載入、ABI 不相容、取消、I/O 錯誤與內部錯誤。不得讓 Rust panic 展開跨過 ABI；不承諾能攔截程序 abort、存取違規或所有 decoder 問題。
- 工作尚在執行時，不得釋放 handle、卸載程式庫或釋放背景執行緒仍使用的記憶體。
- 程式庫只從 File Workbench 管理的安裝位置按平台／架構載入，先檢查 ABI 與版本；不從掃描來源、目前目錄或任意 PATH 搜尋同名程式庫。

## 非功能需求與平台

- **可重現性**：固定上游 commit、lockfile、Rust 工具鏈與建置功能；記錄產物版本、目標平台及驗證資料集。
- **效能**：依 ADR-011 的資料規模量測冷／暖快取、各階段耗時、重掃、I/O、記憶體及 UI 回應；不得由未量測的宣稱決定預設值。三級規模仍以 ADR-011 的決策為準。
- **資料保護**：測試使用可重建資料與隔離的 `FWB_DATA_DIR`。引擎可寫分配的暫存／快取，不能寫掃描來源；來源離線、權限不足、雲端佔位檔及連結政策由 Core 一致處理。
- **跨平台**：Windows x64 先驗收；其他平台要先通過核心契約與各自檔案系統測試，才能標示支援。UI 移植、路徑／來源身份、回收、啟動及安裝整合另行驗證。
- **部署**：終端使用者不需 Rust 工具鏈；原生產物與選配相依隨套件記錄。MIT、原生選配相依及既有 ImageSharp 授權各自依實際打包內容處理；引擎切換不會自動移除 C# 專案的套件相依。

## 驗收情境

| 編號 | 情境與通過條件 |
|------|----------------|
| AC-E01 | GUI 與 CLI 對同一功能取得一致的能力／可用性資訊；未支援與缺相依有明確訊息，不產生零結果的成功任務。 |
| AC-E02 | 具已知答案的精確去重資料含改名副本、同大小不同內容、空檔與跨來源副本；各宣告支援的引擎各自符合答案。 |
| AC-E03 | 完整清單仍包含不重複檔案；候選集合每項皆有終態，排除、連結、雲端與離線規則一致，不由上游預設值縮小範圍。 |
| AC-E04 | 建立任務後變更預設引擎／參數，再暫停與重開；原快照不變，缺少原版本時不換引擎執行。 |
| AC-E05 | 大型批次分析可持續顯示階段並接收取消；部分結果不替代完整世代，重開後可識別中斷，已提交索引不遺失。 |
| AC-E06 | 舊索引升級、混用不同算法、重新分析及還原皆不混比指紋；切換後舊計畫重新驗證，沒有 Rust DLL 仍能檢視歷史及還原。 |
| AC-E07 | DLL 缺失、錯誤架構、ABI 不符、無效參數、重複取消與反覆建立／釋放工作有受控結果；沒有洩漏、越界或提前釋放。 |
| AC-E08 | 相似圖片以標註資料量測誤判與漏判；距離與閾值可解釋，候選不觸發精確重複的自動操作路徑。 |
| AC-E09 | 偵測、取消、比較引擎與錯誤注入都不變更掃描來源；實際變更仍經審閱、確認、重新驗證、執行與還原測試。 |
| AC-E10 | 交付 Windows 安裝／更新包時，乾淨環境不需 Rust 工具鏈即可分析，切換／缺少可選引擎可診斷；原有 C# 功能與 CLI 格式無非預期變更。 |
| AC-E11 | 每個宣告支援的平台記錄版本與檔案系統案例；尚未驗證的平台／能力保持未支援或實驗性，不沿用 Windows 的驗收標章。 |
