# 圖片候選審閱

Windows WPF 的「圖片審閱」頁使用實驗性 Czkawka 圖片能力。它保存候選與
人工判斷，與精確內容工作台的操作決定分開。來源檔案不因審閱而搬移、
刪除或合併；距離 0 也不會成為精確內容相同的證據。

## 操作流程

1. 在「來源」加入一個或多個資料夾，設定排除規則。待主掃描閒置後，
   開啟「圖片審閱」。本次分析使用當下線上來源與凍結的規則／身份。
2. 設定「新分析上限」，按「尋找候選」。預設距離 6 bits；越低越嚴格。
   此設定只作用於新分析，不會重新解讀畫面上已保存的結果。
3. 選擇候選配對。左右預覽均會重新檢查本機可讀狀態、來源政策與原檔案觀察。
   改變、離線、雲端檔或無法確認的圖片不提供可標記的預覽。
4. 按「標記相關」、「標記不同」或「清除判斷」。判斷會自動保存為審閱註記。
   配對清單支援上下鍵與捲動，判斷可逐組保留。
5. 以「開啟已存審閱」選擇目前資料目錄的 `image-reviews/review-*.json`。
   不需要原生引擎就能載入既有紀錄；預覽仍需要原來源檔案及身份吻合。
   「本次分析來源」及「分析紀錄」顯示保存的範圍、算法、閾值與版本。

離頁會取消進行中的分析、紀錄載入及尚未開始的預覽。合作取消等待 backend
停止，已保存的索引與檢查點保留。已完成分析的最後紀錄寫入會收尾完成。
解碼與檔案系統呼叫可能延遲取消，沒有宣告程序隔離或可強制終止 decoder。

## 算法與限制

算法 `image-mean8-d8-v1` 使用 Mean 8×8、Lanczos3，以及旋轉／鏡射變形間的
最小 Hamming distance（0–64 bits）；介面可選 0–16。僅啟用 PNG／JPEG。
標註資料中的縮放、重壓縮與旋轉可形成候選，裁切可能漏判。
6 bits 基準的 TP 6／FP 0／FN 4／TN 11 是微型合成 corpus 結果，
不是個人照片正確率承諾；詳見[圖片適配紀錄](research/2026-10-24-similar-images.md)。

每來源最多解碼 2,000 張，全域配對在各來源完成後最多比較 2,000 張、
產生 10,000 對。因此多來源的總解碼量仍可能超過 2,000 張。
超限、部分失敗、缺證據及取消皆不回報完整候選清單。
原生輸入預先檢查 32 MiB／24 megapixels；不是程序記憶體的硬隔離。

預覽在背景依序解碼，每張最長邊最多 700 pixels，兩軸都檢查上限，
小圖不放大。快速切換只保留最新選擇的畫面。沒有載入完整資料夾的縮圖牆，
候選清單採虛擬化顯示。

## 保存與相容性

每輪使用獨立 `analysis-<id>.db`，含完整 inventory、來源／引擎快照、世代、
逐檔證據及錯誤。圖片證據保存於既有版本化證據表；獨立的感知發布入口
不啟用 `files.hash`，也不寫入主工作台的計畫或執行歷史。

審閱檔格式版本 1 只保存圖片資料與必要的來源／工作 metadata，最多 2,000 張、
10,000 對及 500 個錯誤，檔案上限 64 MiB。優先保留全部配對成員；
其餘診斷超限會標示縮短，完整清單仍在索引。來源資料不包含於審閱檔。

載入會驗證格式、來源規則、檔案觀察、配對成員、距離與判斷。
寫入使用同目錄暫存與原子換檔；保存判斷時會核對載入內容的 SHA256 revision，
並使用每檔保存鎖及 `.lock` 檔。舊視窗或檔案被替換後的判斷不會靜默覆寫，
需重新開啟紀錄。索引與審閱格式不因此降版，舊 0.1.0 分析任務仍需原版引擎。

只讀取目前應用資料目錄內的審閱檔；拒絕審閱目錄被 junction 改指向來源，
不從匯入紀錄解析或載入任意 DLL。發佈與 staging 仍依 PLAN-002 Phase 5，
ImageSharp Release 授權及非 Windows 驗收仍待完成。
