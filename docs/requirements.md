# File Merge Assistant 產品需求

狀態：Draft。最後更新：2026-10-23。

File Merge Assistant 的目標是讓使用者透過 Windows GUI，持續整理分散在不同資料夾與硬碟的檔案。使用者可以分次加入來源、累積檔案索引，並在看懂差異與影響後，決定保留哪些版本及處理哪些副本。

本階段建立需求與設計依據。畫面 layout 由後續設計人員規劃；本文件不代表功能已交付，也不代表資料庫、去重引擎或安裝格式已選定。

## 已確認的方向

- GUI 是主要操作介面。一般整理流程不應要求使用者開啟 CLI 或修改設定檔。
- 需要管理多個資料夾，讓它們加入任務佇列，逐步建立可持續累積的本機索引。
- 之後加入新資料夾或重新連接硬碟時，可以與已建立的索引比對。
- 使用者需要理解保留與處理的依據，並在執行前審閱變更。
- 目前先完成文件；layout、技術選型與實作分開處理。

## 使用情境

### 分批整理多年備份

使用者先掃描電腦中的照片庫，隔天加入外接硬碟備份。第二次掃描應沿用第一天的索引，找出跨來源的重複項目，不必把所有硬碟同時接上並重新掃描。

### 保留可信來源中的版本

使用者指定「照片原始檔」為受保護來源，審閱其他備份中的副本。系統可以提出保留建議，但要顯示理由，讓使用者調整及保留多份必要副本。

### 中斷後繼續整理

掃描期間可能遇到程式關閉、權限不足、檔案被使用或外接硬碟拔除。使用者重新開啟程式後，應知道哪些工作已完成、哪些需要重試，以及目前結果涵蓋的範圍。

## 現有版本與目標的差距

以下基準為程式碼版本 `0754699`。元件存在不等於已完成 GUI 工作流程。

| 能力 | 現有行為 | 目標需求 |
|------|----------|----------|
| 掃描來源 | GUI 一次一個根目錄；CLI 可用 `--also` 在同一次任務掃多個來源 | GUI 管理來源清單並分次排入任務 |
| 結果保存 | 掃描完成後寫入 JSON；相同輸出路徑會覆寫舊結果 | 完整檔案索引可累積、查詢及重新比對 |
| 快取與監控 | 有服務與設定欄位，尚未接入目前 GUI／CLI 掃描流程 | 明確的增量掃描與任務恢復行為 |
| 重複判定 | 有內容雜湊、名稱與影像指紋相關程式碼；GUI 以雜湊相等分組 | 區分內容相同、相似影像與同名候選 |
| 檔案審閱 | 文字列表、metadata 與保留勾選 | 能判斷差異的對照資訊、預覽及保留理由 |
| 執行整理 | GUI 自動保留按鈕會直接呼叫執行；Dry Run 預設未勾選 | 保留建議先形成待審閱計畫，再確認執行 |
| 還原 | GUI 提供專用回收區與全部還原 | 按操作批次追蹤結果，清楚標示可還原範圍 |

現行實作依據：[GUI 掃描](../src/Gui/ViewModels/ScanViewModel.cs)、[CLI 掃描](../src/Cli/Commands/ScanCommand.cs)、[JSON 儲存](../src/Core/Services/JsonScanResultStore.cs)、[重複判定](../src/Core/Services/DuplicateDetector.cs)、[GUI 整理](../src/Gui/ViewModels/ResultsViewModel.cs)。建置與測試限制另見 [testing.md](testing.md)。

## 第一階段需求草案

P0 表示第一個完整工作流程必須具備；P1 表示後續擴充。以下均為待審閱需求，不能以現有方法或按鈕名稱判定完成。

| 編號 | 優先序 | 需求與驗收重點 |
|------|--------|----------------|
| FR-001 | P0 | 管理多個來源資料夾，設定子目錄、排除條件與保護規則；重複或重疊路徑不能把同一檔案重複計數。 |
| FR-002 | P0 | 來源可以加入佇列、調整未開始工作的順序、暫停、繼續、取消及重試；掃描中仍可加入新工作。 |
| FR-003 | P0 | 保存所有已掃描檔案的索引，包含非重複檔；關閉程式後仍保留來源、任務與索引結果。 |
| FR-004 | P0 | 重新掃描時沿用有效指紋，只處理新增、變動或需重新驗證的項目；中斷後可從已保存的進度繼續。 |
| FR-005 | P0 | 使用者可以指定比較哪些來源，以及比較來源內或跨來源；顯示結果的新舊程度與掃描完整性。 |
| FR-006 | P0 | 內容重複群組可以檢視路徑、大小、日期、來源、判定依據與保護狀態；照片提供預覽，其他類型提供必要資訊及開啟位置的操作。 |
| FR-007 | P0 | 保留建議可解釋、可覆寫，允許保留多份；選取、排序、套用規則都不會立即修改原始檔案。 |
| FR-008 | P0 | 操作先形成可審閱計畫，列出保留檔、處理檔、方式與預估影響；確認執行前重新驗證來源及相關檔案。 |
| FR-009 | P0 | 逐項記錄操作成功、失敗、略過及還原結果；還原遇到路徑衝突時不可覆寫現有檔案。 |
| FR-010 | P0 | Windows 使用者可直接啟動 GUI，查詢索引、審閱結果及完成整理；資料位置不應隨啟動工作目錄改變。 |
| FR-011 | P1 | 相似照片以可調整的相似度條件找出候選，提供對照；候選不得自動當成內容相同而刪除。 |
| FR-012 | P1 | 擴充影片相似比對、報告／腳本匯出，以及背景檔案變更監控；每項另定驗收條件。 |

第一階段先交付 FR-001 至 FR-010 的完整流程。相似影像的設計狀態需在 layout 草案中預留，但不以尚未驗證的辨識能力承諾交付。

## 使用與資料安全要求

- 查詢、預覽、選取保留版本及提出規則建議，不修改來源檔案。
- 移除來源、取消任務、清除索引與處理原始檔案是不同操作；移除來源或索引紀錄本身不刪除原始檔案。
- 每個內容重複群組至少保留一份經驗證的檔案；允許使用者明確保留多份。
- 受保護來源可以參與比對，但不能成為移除目標。來源無法連線、權限不足與尚未完成掃描，都不能當成檔案已不存在。
- 索引中的指紋需要保留演算法及版本資訊。不同類型或版本的指紋不能直接混合比較。
- 執行前驗證待處理檔與保留檔的現況；檔案變動、缺失或判定依據不足時，對應操作轉為待更新或略過。
- 第一階段的移除流程採可追蹤的回收／隔離方式。永久刪除、清空回收區與連結替換不作為預設流程。
- 顯示重複邏輯大小、計畫處理大小及實際回收狀態的差別。移入同磁碟的回收區不等於立即釋放容量；hardlink 也不能重複計算實體空間。
- 掃描進度尚無可靠總數時，顯示階段與已處理數，不製造精確百分比或完成時間。

## 品質要求

- **持續性**：任務進度分批保存；中斷不應破壞已提交的索引。取消任務與刪除既有索引是不同動作。
- **可操作性**：掃描與大量列表載入期間，仍能瀏覽結果、檢視錯誤及發出暫停要求。
- **可理解性**：使用者能回答目前掃到哪裡、結果有多新、哪些檔案會變動，以及哪些操作可以還原。
- **本機資料**：核心流程在本機完成，不要求帳號或上傳檔案。預覽及索引資料的儲存與清理方式需要明示。
- **可量測性**：實作計畫須定義測試資料量、硬體、掃描耗時、記憶體及 UI 回應量測方式；目前不承諾未量測的效能數字。

## 本階段範圍

本次產出產品需求、工作流程規格與設計交接文件。後續設計者決定資訊如何分頁、分區、呈現及操作；現在不指定側欄、卡片、欄位寬度、配色或控制項樣式。

雲端同步、多使用者協作、自動合併檔案內容，以及無人審閱的相似檔刪除，不在第一階段範圍。檔案索引與資料庫的備份、來源資料的備份及回收區，須作為不同概念處理。
